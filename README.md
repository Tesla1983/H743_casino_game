# STM32H743 老虎机（真随机驱动）

English version: [README_EN.md](README_EN.md)

独立工程，只依赖一块 **STM32H743**（CH340 串口，`$?RND,<n>` 协议），不依赖任何其他开发板或工程。

核心思路：**STM32H743 片上 TRNG 提供物理真随机熵**，主机侧用 **ChaCha20 DRBG** 把它扩展成密码学安全的字节流；游戏程序（`slot_machine.html` 老虎机、 `baccarat.html` 百家乐）用这些字节驱动完整的游戏逻辑——滚轮 / 发牌、赔付、计分、渲染全在主机端完成。真随机只决定"停在条带哪一格 / 发到哪一张牌"，符号分布与赔率表决定长期概率。

---

## 一、STM32H743 硬件

- **主控芯片**：STM32H743VIT6，内置 **TRNG**（真随机数发生器，模拟环形振荡器）。
- **通信**：CH340 串口（USART1），协议 `$?RND,<n>` 供字节；`$?PING` / `$!PONG` 用于认板，`$?VER` / `$?STAT` 为最小固件专有。
- **固件**（最小固件 `firmware/`，RNG dongle）：只做 RNG + 串口——2 988 B flash、烧录 2.3 s、复位到应答 `$?PING` 仅 3 ms、串口吞吐 11.0 KB/s。
- **开串口不复位板子**：先 `dtr=True, rts=False` 再 `open()`，避免 RTS(NRST) 低脉冲把板子意外复位。
- **只读操作**：桥只发 `$?PING` / `$?RND,<n>`，不写 flash、不动 option bytes、不主动拨 BOOT0/NRST。
- **串口独占**：桥运行期间长期持有该 CH340，同一时刻别的程序打不开。

## 二、游戏介绍

本工程现已包含 **两个游戏**，均由同一颗 STM32H743 的物理真随机驱动：

- **老虎机（slot_machine.html）**：5 个滚轮 × 每轮可见 3 行（上 / 中 / 下），共 9 条 payline，含 `wild`（百搭）与 `scatter`（散财）；滚轮、赔付、计分、渲染全在主机端完成。
- **百家乐（baccarat.html）**：与本工程共用同一条随机链与同一个钱袋，同样由 H743 物理熵驱动。

两个游戏只差"怎么消费随机字节"（条带分布 / 赔率表 / 发牌规则）；**真随机只决定"下一个结果落在哪一格 / 哪一张牌"，长期概率由游戏规则决定，与随机源无关**。

### 真随机驱动：为什么选 H743 硬件 TRNG

开发前期调研对比过多种熵源（硬件 TRNG / 主机 OS CSPRNG / 预置随机种子表），最终选 **STM32H743 片内 TRNG** 作物理熵源，核心优势：

- **真物理熵，非算法伪随机**：H743 的 TRNG 是片内**模拟环形振荡器**采样的硬件外设，熵来自物理噪声，理论上**不可预测、不可复现**；区别于浏览器 `Math.random` 或任何"种子表"（拿到种子即可重放整条流）。
- **硬件自带健康自检**：固件每次取数都读状态寄存器检查 **SECS / CECS**（种子错误 / 时钟错误），一旦置位就"关-延-开"恢复、丢弃前两字后重试，连续 4 次仍失败才报错——**硬件层面保证吐出的字节确实来自健康熵源**。
- **独立于主机**：TRNG 是芯片专用外设，不受主机 CPU 负载、操作系统状态、进程调度影响；离线虽可用 OS CSPRNG 零配置兜底，但那是内核确定性算法，事后无法逐字节证明其"没被预测"。
- **密码学安全扩展**：物理熵经 **ChaCha20 DRBG**（RFC 8439）放大成可用字节流，每块输出后 **rekey**（拿到后续输出也推不出前面的），每 8192 B 用新派生熵重播种（前向保密）；**熵源与扩展职责分离**。
- **统计质量达标**：在 20 万–100 万字节上，256 桶卡方 / 单比特 / NIST 游程 / 序列相关 / 扑克 五项检验**全部通过**（α=0.01），对齐 GLI-11 / NIST SP 800-22 常用项。

一句话：**H743 提供"真实、健康、独立"的物理熵，主机侧 DRBG 把它放大成可安全使用的随机流**——这是本架构选硬件 TRNG 而非纯软件方案的根本原因。

#### 横向选型：抽奖类设备视角

抽奖机、老虎机等抽奖类设备的核心诉求是**结果不可预测 + 均匀分布**——让每个参与者概率均等、无法被玩家或运营方操纵。这与金融加密、密钥生成有本质不同：通常**不必追求"全熵"**（每比特都蕴含 100% 真实随机）那样苛刻的标准，一个通过标准统计随机性测试、无明显规律与偏见的硬件 RNG 即足够（监管严格的博彩设备除外，可能有强制认证）。

以此为前提，对四款常见带 TRNG 的 MCU 重新评估：

| 芯片 | 随机数质量（关键依据） | 抽奖机场景适用性 |
| :--- | :--- | :--- |
| **STM32H743** | NIST 官方"全熵"认证（1 bit/bit） | **质量天花板，性能有富余**。RNG 质量远超一般需求，提供最坚实的公平性基础；官方文档将其列为"随机数抽奖"应用之一。预算与开发资源允许时，选它不会在随机性上出任何问题。 |
| **ESP32-S3** | 实测熵值极高（≈7.9998 bit/Byte），无官方全熵认证 | **极高性价比的强力候选**。物理熵质量对抽奖绰绰有余，且集成 Wi-Fi/蓝牙，便于联网与远程管理，显著降低系统成本与复杂度。 |
| **RA6E2** | 量化熵值明确（0.872315 bit/bit），有内部评估报告 | **功能匹配的均衡之选**。官方资料将"抽奖类设备"列为 TRNG 典型应用，有数据支撑的可靠随机性；作为入门级 MCU，成本上可能更有优势。 |
| **RP2350** | 有专用 TRNG，但公开量化熵值数据较少 | **需额外验证的选项**。社区讨论提到其基于 ROSC 的方案可能随机性偏低，需仔细配置；对公平性要求明确的场景，选它意味着需自行承担更多验证工作。 |

**选型建议**：逻辑应从"追求绝对最高质量"转向"在公平性达标的前提下，寻找成本、集成度与开发便利性的最佳平衡点"。

- **最无可争议的公平性背书**（商业 / 受监管环境）：**STM32H743VIT6** 仍最稳妥——其 NIST 全熵认证是应对任何随机性质疑的终极答案，本工程即在此列。
- **高性价比 + 系统集成度**（需联网、远程管理的智能抽奖机）：**ESP32-S3** 是强力竞争者，实测随机性完全满足需求，内置无线大幅简化设计。
- **成本敏感 + 需明确数据支撑**：**RA6E2** 合适，官方推荐用于抽奖设备，量化熵值足证公平。

> **关键提醒**：无论选哪款芯片，正式抽奖产品的业界最佳实践是**以硬件 TRNG 作种子，驱动软件 CSPRNG，并定期用新的 TRNG 数据重新播种**——同时保证随机数的质量、均匀性与生成速度。本工程的 ChaCha20 DRBG 正是这一做法（物理熵 → DRBG 放大 → 周期性重播种）。

两种接入方式：**在线**——向板子实时发 `$?RND` 取物理熵；**离线**——把物理熵在空闲时采成快照文件，离线桥只读文件、不占串口，可与在线并存。仓库已随附 `random_raw.bin`（1 MB，由 H743 硬件 TRNG 采样得到的真随机文件），没有板子时离线桥可直接用这份文件演示，无需现场采熵。两路最终汇于同一条无偏映射（`byte % 64`），对游戏概率无任何区别。

## 三、运行

```bash
# 一键启动（推荐）：拉起两个 H743 随机源桥 + 打开游戏页面
py start_casino.py
#   —— 双击即可。内部依次：① 确保 h743_entropy.json 可用（缺失/超30天/校验失败则
#      趁串口空闲自动重采）；② 起在线桥 8765（H743 串口直供）；
#      ③ 起离线桥 8770（快照 + DRBG，不占串口）；④ 打开 slot_machine.html；
#      ⑤ 作为看守进程（Ctrl+C 一并结束两个桥）。可选：--no-browser 只起桥不开页面。
```

> 系统 Python 3.12 已装 pyserial（默认 `python` 是 3.13、**无** pyserial），用 3.12 跑。
